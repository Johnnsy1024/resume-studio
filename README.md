# 简历工坊

一个无需账号、在本机运行的简历编辑器。支持实时 A4 预览、自动分页和保留可复制文字的 PDF 导出。

## 在另一台电脑使用

项目仓库：<https://github.com/Johnnsy1024/resume-studio>。这是私有仓库，需要登录有访问权限的 GitHub 账号。

先安装 **Node.js 22.18 或更新版本**（推荐 Node.js 22 LTS）和 **Google Chrome**。代码支持 macOS、Windows 和 Linux；扫描 PDF 的本机文字识别目前仅支持 macOS。

已安装 Git 时，在终端运行：

```bash
git clone https://github.com/Johnnsy1024/resume-studio.git
cd resume-studio
npm ci --registry=https://registry.npmjs.org
npm run build
npm start
```

打开 <http://127.0.0.1:4317>。运行期间保持终端开启，关闭服务时按 `Control + C`。

没有 Git 时，可登录 GitHub 后在仓库页面选择 **Code → Download ZIP**，解压并进入项目文件夹，再运行上面的 `npm ci`、`npm run build` 和 `npm start`。

macOS 也可以在安装 Node.js 后，双击 **启动简历工坊.command**，它会自动安装依赖、构建服务并打开浏览器。如果下载 ZIP 后无法双击执行，在项目终端运行 `chmod +x 启动简历工坊.command`。

首次安装依赖需要联网，编辑和导出无需联网。PDF 导出使用本机 Chrome 或 Edge；未自动找到浏览器时，可以设置 `CHROME_PATH`，或者使用“更多操作 → 浏览器打印”。打印时选择 A4、100% 缩放，关闭浏览器自带页眉页脚。

### 将已有简历带到另一台电脑

在原电脑中打开需要迁移的简历，选择 **更多操作 → 备份 JSON**，把文件复制到另一台电脑，再使用 **导入 → JSON 备份** 恢复。JSON 会包含文字、照片和排版设置，多份简历需分别导出。

GitHub 只保存程序代码，个人简历不会上传，也不会在两台电脑之间自动同步。

### 更新程序

停止服务后，在项目文件夹运行：

```bash
git pull --ff-only
npm ci --registry=https://registry.npmjs.org
npm run build
npm start
```

更新程序会保留本机 `data/` 中的简历。如果通过 ZIP 安装，请先备份简历 JSON，再下载新版并导入备份。

## 已有功能

- 编辑基本信息、个人简介、工作经历、项目经历、教育经历、技能和自定义模块。
- 添加、删除、排序条目与模块；隐藏模块；支持撤销、重做。
- 四种单栏版式，六种预设配色、自定义颜色，内置中文黑体、系统宋体与等宽字体。
- 调整正文字号、行距、模块间距、页边距、页眉对齐方式和页码。
- 上传 JPG、PNG、WebP 照片，在本机裁切、缩放、调整位置、压缩及设置形状。
- 实时 A4 分页；标题随首段一起换页；超长段落继续排入下一页。
- 一键适配：逐步调整间距、页边距和字号，尽量排成一页。内容过多时保留多页，不删改经历。
- 检查联系方式、基本信息、日期顺序、描述长度与篇幅；统一空格和列表格式。
- 多份简历、空白简历、示例、副本、重命名；自动保存和刷新恢复。
- PDF、Markdown、JSON 备份导出；JSON 恢复；按常见标题整理纯文本或 Markdown 导入。
- 直接导入 Word（.docx、.doc）或 PDF，自动识别联系方式、经历、日期、教育和技能，导入后继续编辑。支持常见表格、双栏、扫描版及图文混合 PDF。
- 桌面双栏编辑，手机可切换编辑与预览；预览缩放和全屏。

“检查”“整理”和导入按本地规则处理，不调用大模型，不编造经历或成绩。语言切换只调整页眉和简介标题，正文及模块名称可自行填写英文。目前不导出 Word。

## 导入 Word 或 PDF

1. 点击右上角“导入”，选择“Word / PDF”。
2. 选择或拖入简历文件，等待自动识别。可查看识别原文；找到适合的文档图片时，可选作简历照片。
3. 点击“导入并排版”。会创建一份新简历，随后可以编辑全部文字、模块、日期和外观，继续保存或导出 PDF。

支持 `.docx`、旧版 `.doc` 和 `.pdf`，单个文件最大 20 MB；PDF 最多 30 页，提取文字最多 6 万字符。Word 正文、常见表格和文本框会读取为文字；PDF 按文字位置恢复阅读顺序。无法分类的文字保留在可编辑的“导入内容”或“其他个人信息”中。

扫描页通过 macOS 自带的文字识别转换为可编辑内容。首次会自动编译本机识别工具，需要 macOS 命令行工具；尚未安装时，在终端运行 `xcode-select --install`，完成后重新导入。图片较模糊时，姓名、数字和日期可能有识别误差，可在编辑器中修正。带密码的文件需先解除保护。其他系统支持文字版 PDF 与 Word，扫描识别目前仅支持 macOS。

导入采用当前模板重新排版，原文件的分页、字体和装饰不会照搬。`.docx` 和常见文字 PDF 中符合尺寸的图片会提供为照片候选；旧版 `.doc` 和整页扫描图中的人像可在“照片”中另行添加。

## 数据保存

内容保存在 `data/<简历编号>.json`，照片嵌入同一份文件。每次保存保留上一版 `.json.bak`；删除的简历移动到 `data/trash/`。浏览器中另存最近尚未写入文件的草稿，刷新时恢复。

建议定期通过“更多操作 → 备份 JSON”下载独立备份。`.bak` 若需恢复，先停止服务，保留现有文件，再将备份复制为原来的 `.json` 文件。

服务只监听 `127.0.0.1`，不使用账号、分析埋点、远程字体或外部模型接口。`data/` 已被 Git 忽略。默认中文字体随应用提供，采用 [Noto Sans SC](https://github.com/google/fonts/tree/main/ofl/notosanssc)，使用 SIL Open Font License；字体不会从远程地址加载。

## 开发与检查

```bash
npm run dev
npm run check
```

`npm run dev` 使用 Vite 中间件，修改后刷新浏览器查看。`npm run check` 运行数据校验、列表整理、分页边界、本机存储和备份测试，再进行 TypeScript 检查与正式构建。

自动检查会在 macOS、Windows 和 Linux 上安装依赖、运行测试并构建。

本机验证：19 项核心测试与正式构建通过。使用 Playwright 和本机 Chrome 实测了内容编辑、撤销重做、自动保存、刷新恢复、四种版式、照片裁切、PDF 下载、JSON 恢复、Markdown 导出、模块及条目排序、保存失败后的草稿恢复、无效文件提示、全屏与打印。验证尺寸包括 1586×992、1440×1000、1280×800 和 390×844。当前没有 Browser 插件，因此使用 Playwright 验证；Safari、Firefox 未单独验证。

文件导入另用真实生成的中文和英文 Word、旧版 `.doc`、Word 表格双栏、文字版 PDF、双栏 PDF、扫描 PDF、混合 PDF 验证。核对了姓名、联系方式、多条工作经历及日期、教育、技能和照片；导入后修改、刷新恢复、切换版式、重新导出 PDF 均已实际运行。加密、损坏、空白和页数过多的文件会给出错误信息，原有简历不受影响。

长内容在预览中从 5 页压缩到 3 页，逐段对比未丢失文字；导出的 PDF 也为 3 页，并通过文字提取核对了所有重复段落。单页 PDF 同时核对了中文姓名、公司、学校和嵌入照片。默认黑体采用本机随应用提供的字体，修复了系统字体导致部分汉字复制为兼容偏旁的问题。验证期间未发现浏览器错误或外部网络请求。

可配置项：

```bash
PORT=4318 npm start
RESUME_DATA_DIR=/你的数据目录 npm start
CHROME_PATH='/浏览器可执行文件路径' npm start
```

## 界面设计

使用白色编辑区、浅灰预览画布和深绿色操作按钮。桌面左侧编辑、右侧 A4 预览；手机可切换编辑与预览。初始视觉参考由 Image Gen 生成，实际界面已在浏览器中验证布局、字体、颜色、照片和分页效果。
